# Operator composition candidates

The operator connects a TikTok room, tunes speech and music, triggers ritual RPC actions, simulates a comment, and reads the response and recent events.

1. **Stage beside controls.** Keep a live preview beside a short control column. This links operator action to its result but gives less room to command and event detail.
2. **Status-first workspace.** Put room and audio status before controls. This answers whether the stream is ready, then exposes the available actions.
3. **Task tabs.** Separate live, ritual, and simulation work into tabs. This is compact but hides important controls from each other.
4. **Event-focused workbench.** Put the connection and audio controls first, ritual actions in the main work area, and recent events plus the RPC response in a secondary area. This keeps the common actions visible while retaining feedback.
5. **Setup sequence.** Move from connection through sound setup to a first test. This supports first run but slows repeat operations.
6. **Command rail.** Pin common actions in a left rail and show details in the work area. This saves vertical space but makes action names harder to scan.
7. **Grouped action register.** Keep all event commands together and put connection, audio, and response below them. This foregrounds rituals but delays readiness checks.

The roll assigned candidate 4. Build a responsive event-focused workbench with familiar web controls. The sớ world contributes palette, type, density, and the active-seal mark only; it does not turn tables or controls into a paper form.
